# Working on envoy

envoy runs headless AI-session turns — the `claude` or `codex` CLI — as caller-named jobs and returns each as files: `result.md` is the answer, `meta.json` the machine-readable record, `progress.log` the live view, `raw.log`/`stderr.log` the verbatim streams. Agents following the consult, review and delegate skills drive it, and so does a program, the planlab steward; all of them read its stdout as a prompt. It is judgment-free mechanism — no retries, review loops or provider selection — and a feature that wants judgment belongs in a caller. `docs/README.md` owns the design and routes to a doc per domain; read the owning doc before changing behaviour, and `EVIDENCE.md`, the dated log of what each lesson cost, before revisiting a settled question. Add to it when usage teaches something new; `/improve-tool` mines real usage for the next improvements.

One verb dispatches: `envoy run <job> --prompt-file F --with <voice>…`. A voice is a cold session (`provider[:model[:effort]]`) or a finished job's conversation (`@<job>`, `@<job>/<member>`). One voice runs flat in the job directory; several run as a **fan-out**, a supervisor over unchanged turns: each member is an ordinary turn, the group adds only supervision and presentation, and anything that would give a fan-out turn semantics of its own belongs in a caller.

- One maintainer's tool: commit on `main`, push at milestones, and keep changes proportional to demonstrated failures or requested features. Dependencies: the standard library, clikit and Kong.
- **Contracts other repositories depend on:** stdout blocks, the `next:`, `resume:` and `stop:` lines and refusal wording → the consult, review and delegate skills (`~/dotfiles/claude/.claude/skills/`); `run` argv, exit codes 0–6, `lock error:` on exit 3, `meta.json` schemas 10 and 11, and `envoy version` → the planlab steward (`~/dev/planlab/main/services/steward/src/kernel/turn_runner.ts`); `envoy run|collect <job>` argv with every option that takes a value, and the `job:`, `fan-out:`, `status:` and `=== member` lines → claude-steps (`~/dev/claude-steps/internal/record/`). `TestContracts` pins each byte for byte (`ENVOY_CONTRACT_UPDATE=1` accepts an intended change, reviewed as a diff); the help pages are `TestHelpPages`' (`make golden`), and what each must teach `TestHelpPagesTeach`'s. A change to one updates its consumers in the same pass and bumps `version` in `cmd/envoy/main.go`.
- Tests never touch live state: every suite runs under a temporary `HOME` (job store, locks, transcripts) against the fake provider in `tests/fake-bin/`, never a real `claude` or `codex`, and needs `node`. `cmd/envoy`'s `TestMain` clears the environment, so a developer's `ENVOY_CODEX_CMD`, `CLAUDE_CODE_SESSION_ID` or `CLAUDE_CONFIG_DIR` cannot reach the engine, and makes the test binary envoy for the hidden entries, so the real detach chain runs under `-race`; `tests/` drives a race-built binary for signals and process groups. The `ENVOY_*_MS` knobs shrink the lifecycle — test rig, not user configuration.
- Ship: `make check`, then `make install`. Callers run `~/.local/bin/envoy` and keep the old build until then; the mini keeps its own until `twin sync envoy`, and the steward its own pinned copy (`host/versions.json`). Edit a skill that teaches the contract only after `make install`: a skill ahead of the installed binary hands callers a surface it rejects (`EVIDENCE.md`, 2026-07-26 and 2026-08-28).
- The command line runs on clikit: how help renders and how argv errors read are clikit's (`~/dev/clikit`). Help, results and errors an agent reads follow `~/dotfiles/claude/.claude/skills/prompt-engineering/SKILL.md`; library questions go to `~/.agents/skills/find-docs/SKILL.md`.

## Who owns what

The packages and how a dispatch flows through them: `docs/README.md` § How a dispatch flows.

- **`cmd/envoy` only translates**: the grammar, declared once as Kong structs, and one call into `internal/` per command. A refusal made before anything runs comes back unprinted with its exit code and clikit prints it once as `envoy: error: <body>`; a line the engine prints while it reads records or runs a turn (`lock error:`, `collect error:`, the runner's) is the engine's. Held by `TestARefusalKeepsItsLinesUnderOnePrefix` and `TestContracts`.
- **`internal/dispatch/roster.go` resolves every voice the same way.** A cold voice, a continued job and each member of a continued fan-out become one `voice`, pass one set of roster checks (a conversation once, one tree and one anchor, `--instructions-file` matching every continued conversation's own, write intent only on a single voice) and become one `runner.Options`; cardinality then selects the flat or fan-out layout and nothing else. Member addresses are allocated here. Held by `TestRosterRefusals`.
- **`internal/prose` owns the caller-facing vocabulary**: every situation's wording, one situation, one wording. Surfaces keep only their layout and local diagnostics; everyone else contributes observations (typed fields, cause strings), never situation prose. Its tests pin each sentence's bytes once (`TestStatusLineGlossesEveryNonOKStatus`), and the integration tests assert the tokens a caller acts on wherever the sentence reaches it.
- **`internal/provider` is the extensibility seam.** A driver owns native argv and environment additions and translates its provider's stream into semantic events; the runner consumes only those and **never branches on provider name**. Adding a provider is one driver file and one registry entry, which every surface naming providers (voice parsing, effort validation, the spend-cap check, the help page) reads.
- **`internal/runner` is a single-threaded state machine.** One event-loop goroutine owns all `run` state; helper goroutines only send into its channels, routed through `callCh`. It is instance-clean, which is what lets a fan-out run several in one process, and owns its session lock and its claim on the job directory. Held by the race detector over every suite.
- **`internal/job` owns the record schemas for writer and reader**, so the runner and collect cannot drift. **Records hold facts, never prose**: `collect` renders every command, prescription and failure sentence from them and the directory it read them from. A record of another schema version is refused by name wherever its meaning is read — a record with standing instructions is schema 11 — while naming and `pending` read only its stamp (`job.Stamp`, `job.GroupStamp`), so a schema bump never strands a store's names. `group.json` is a roster plus what the supervisor itself knows, never member state. Held by `TestMetaRoundTripAndSchemaRefusal` and `TestAnEarlierSchemasJobsLeaveTheirNamesWorking`; why: `docs/records-and-collection.md`.

## Invariants

The output is a prompt surface: changing wording is a contract change. Every non-ok status says what happened, what it rules out and the one action to take next; recovery prescribes only what the engine observed — prompt state `accepted` → resume, never redispatch; `not_started` → one identical retry; `unknown` → absence of output is not proof of no work (`TestRecoveryCoversEveryPromptState`); and the engine hands over runnable commands. A continuation names the job (`--with @<dir>`) with the prompt file left a placeholder, since a resumed turn needs a NEW prompt; the retry repeats the source conversation, its archived `prompt.md` (with `instructions.md` for a turn that started its conversation) and its settings, spend cap included, under a new name, with the environment resolved at dispatch (`TestRedispatchRepeatsTheDispatch`).

- **The name is the address, scoped to its caller.** The caller chooses the name before dispatch and collects by it. A name means the caller's own newest job under it, else the newest of anyone's (`job.Resolve`); a directory is an identity and never moves. The caller is the session identity the harness exports (`job.CallerEnvKeys`): observed, never derived, never inherited by the provider child. An undelivered job holds its name only against a caller that shares its meaning (`collect.NameHold`, the one definition), on evidence, never on absence. Anything that would let an older job answer to a name is an error, not a fallback; a fallback to another caller's job carries a `note:` line. A refusal that ran nothing gives the name back. Held by `TestANameMeansItsCallersOwnJob` and `TestAnUnreadableRecordNeverYieldsAnOlderGeneration`; why: `docs/naming-and-storage.md`.
- **No model substitution.** Omitted model or effort means the provider's own config governs; the engine reports `(provider default)` and records only what the provider announced. Observed is recordable, inferred forbidden — so a request/report mismatch (`opus` against `claude-opus-5`) is the provider's alias resolution and never gates behaviour. Held by `TestCollectOkBlockDoesNotGuessAtModelSubstitution`.
- **A turn outlives its caller.** `envoy run` waits on a process outside the caller's process group and tree: SIGTERM and SIGHUP stop only the waiting, Ctrl-C and the printed `stop:` command stop the turn, and `envoy wait` restores the completion signal and delivers nothing. Nothing that outlives the caller's command holds the caller's descriptors. Held by `TestATurnOutlivesItsCaller` and `TestTheProviderInheritsNoDescriptorOfTheDispatch`.
- **The waiter-to-detached argv is a protocol across installs.** The waiter parses, then forwards the caller's words unchanged; `make install` renames a new binary in while waiters may be about to exec it, so the detached entry accepts every caller's command line unparsed and the hidden entries keep their names. Held by `TestAnOlderWaitersArgvRunsInTheDetachedProcess`; why: `docs/turn-lifecycle-and-recovery.md` § A turn outlives its caller.
- **A runner is alive while it holds its claim on the job directory**, never because its PID answers: every liveness read goes through `proc.RunnerLiveness`, the PID only for a record without a claim. Held by `TestAClaimedRunnerIsLiveOnlyWhileItsClaimIsHeld`.
- **Process exit and stream EOF are separate observations.** A provider grandchild can outlive the CLI and hold the pipes open, so the whole tree runs in its own process group with exit → grace → SIGKILL. Held by `TestStubbornGrandchildAfterSuccessIsReaped`.
- **The terminal envelope wins** over a timeout that fires during cleanup. Held by `TestCodexTerminalEnvelopeWinsDuringCleanup`.
- **The timeout is a wall-clock deadline, a safety cap, not a stall detector**: laptop sleep must not stretch it, and the engine never acts on quiet — but a capped turn's envelope reports the stream it observed, since a bare cap reads the same whether the provider worked to the deadline or went silent. Held by `TestDeadlineIsWallClock` and `TestTimeoutCarriesTheStreamItObserved`.
- **Session locks are never auto-reclaimed**: a dead runner can leave a live orphan provider, so recovery inspects first. One live turn per session id, including ids that arrive mid-stream; a refusal points at the owning job's collect. Held by `TestStaleLockIsNeverReclaimed` and `TestResumeLockConflictFailsFast`.
- **`collectedAt` means the block reached a caller.** The block is rendered in full, written, and stamped only after the write succeeded; `--status-only`, `pending` and `wait` never stamp; an ok turn whose `result.md` will not read stays owed. Held by `TestCollectStampsOnlyWhatReachedTheCaller`.
- **A collected block is tiered by whether the payload landed, not by status.** An ok turn whose `result.md` reads holds back the diagnostic tier and prints only what the caller acts on; everything else prints in full, and `--status-only` is the full-preamble read. Held by `TestCollectOkBlockHoldsBackDiagnostics`; why: `docs/records-and-collection.md` § The tiered block.
- **A continuation is anchored on job records, not remembered session ids.** `@<job>` reads the session and unspecified settings from the job's `meta.json` (explicit `--cwd`/`--baseline` win, the provider cannot change, the cap is the new dispatch's own), and eligibility has one definition — `continuationOf` in `internal/collect` — consulted by collect's resume line and by dispatch, so collect never advertises a continuation dispatch would refuse. A conversation appears once per roster; a write-recorded source continues alone; every continued turn records `resumedFrom`. Held by `TestRunningJobIsNotAdvertisedAsContinuable` and `TestContinuationRefusals`.
- **Standing instructions belong to the conversation and ride every launch**, because both providers keep the first text only until a compaction and then take that launch's. A continuation passes the source job's `instructions.md`, verified against its record's digest; `--instructions-file` on a continuation must match it; a lost or edited archive cannot continue. Held by `TestStandingInstructionsRideEveryTurnOfAClaudeConversation` and `TestLostOrEditedArchiveBlocksTheConversation`; why: `docs/turn-lifecycle-and-recovery.md` § Continuation.
- **One member's outcome licenses nothing about another.** `6 partial` says results landed *and* a member needs a decision; recovery is per member, with no group-wide retry, and `--allow-write` is refused on a fan-out because members share one tree. A round is not recovery: `@<fan-out>` alone continues every member on one NEW prompt, whole at eligibility, while a session held at dispatch time refuses that member alone. Held by `TestFanPartialOutcomeCollectsPerMember` and `TestFanResumeFromRefusesTheHeldMemberOnly`.
- **A refusal is recorded as what the stream named, never read out of an error's words.** A claude turn the safety classifier refused is `provider_refusal`, with its category and explanation and no fix beside the recovery; an error envelope with no refusal in the stream stays a verdict. Held by `TestClaudeRefusalIsItsOwnCause`; why: `docs/providers.md` § A refusal is a cause of its own.
- **A transient provider error never outranks its verdict.** codex's bare `error` events are observations tallied into `connectionErrors` and acted on by nothing; only `turn.failed` fails a turn, and an observed `turn.completed` with a result is ok whatever came before it. Held by `TestCodexReconnectEventsAreObservedNotJudged`.

## Provider CLI drift

Driver argv baselines are Claude Code 2.1.207 and codex-cli 0.144.1; `--permission-mode bypassPermissions` was checked against Claude Code 2.1.283, codex's `--skip-git-repo-check` against codex-cli 0.162.1, launcher prefixes against codex-cli 0.155.1, Claude usage parsing has captured 2.1.270 coverage, the refusal records were read from 2.1.274–2.1.283 streams, and the standing-instructions flags and their resume and compaction behaviour were read on Claude Code 2.1.296 and codex-cli 0.160.0 (`EVIDENCE.md`). After a provider CLI upgrade, re-check `--help` and the stream shapes before blaming a parser.
